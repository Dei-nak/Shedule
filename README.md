# Shedule — Розклад ІР-31

Статичний сайт для GitHub Pages: автоматичне отримання розкладу, суботні дати, особисті заняття, статистика дня та живий стан поточної пари. Локальний сервер користувачам сайту не потрібен.

## Один раз увімкнути GitHub Pages

1. Завантажте всі файли проєкту, включно з `.github/workflows/pages.yml`, у головну гілку репозиторію.
2. У GitHub відкрийте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
3. Перевірте успішний запуск **Actions → Update schedule and deploy Pages**. Якщо потрібно, натисніть **Run workflow**.

Після початкового налаштування отримання даних і публікація виконуються автоматично. Звичайні зміни коду у VS Code можна завантажувати у GitHub як раніше.

## Як надходять оновлення

- GitHub Actions за розкладом раз на 5 хвилин читає онлайн-книгу Google, знаходить поточний аркуш «ВЕБ, ІР, ІРма» та публікує оновлений сайт. На кожному запуску `gid` визначається заново; архівні тижневі аркуші не підміняють основний.
- Відкрита сторінка щохвилини перевіряє невеликий файл метаданих. Повна таблиця завантажується лише при зміні її версії, без перезавантаження сторінки.
- Поточна пара, завершені заняття і статистика перераховуються кожні 15 секунд. Після повернення на вкладку або відновлення інтернету оновлення запускається відразу.
- Показується час перевірки саме джерела, а не час відкриття сторінки. При збої залишається останній розклад з позначкою давності. Невдала збірка не замінює вже опубліковану версію.

Це періодичне оновлення, а не миттєва передача змін із Google: до інтервалу додається черга GitHub Actions і час публікації Pages. GitHub може затримувати запуски; у публічних репозиторіях також вимикає cron після 60 днів без активності. Обмеження описані в [документації GitHub](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule). Якщо cron вимкнено, його потрібно знову ввімкнути в Actions.

## Особисті заняття

Кнопка **Додати пару** дозволяє обрати будь-яку дату, час, предмет, тип, викладача, посилання та примітку. Власні пари сортуються разом з офіційними і враховуються у статистиці. Кнопка з олівцем відкриває редагування та видалення. Власні записи зберігаються у `localStorage` цього браузера, переживають оновлення джерела та публікації сайту; між пристроями не синхронізуються. Очищення даних браузера видаляє їх.

Панель **Ритм дня** під денним розкладом показує мінікартки часових блоків, кількість завершених пар, навчальний час без подвійного підрахунку накладених занять та типи пар. Натискання мінікартки переходить до відповідної пари. У тижневому режимі панель прихована.

## Джерело та парсер

Звичайне посилання на онлайн-книгу задано в `schedule-config.json`. Якщо університет створить зовсім іншу книгу з новим ID, замініть `source` один раз. Зміни `gid` у поточній книзі обробляються автоматично.

Пари без окремих дат повторюються у відповідний день у межах семестру. Квадратні дужки обмежують дати, а червоні дати додають суботні заняття на час вихідного рядка. Обробляються також пробіли в `(Л )`, коми у `19,10` та зайвий суфікс у `28.09.10-26.10`.

## Локальна робота та перевірки

Потрібен Node.js 20 або новіший. Зовнішні npm-залежності не потрібні.

```powershell
node --test schedule.test.cjs
node build-pages.cjs
```

`dist/` — готовий статичний сайт, який публікує workflow. Він працює й у підпапці репозиторію GitHub Pages.

У VS Code додано завдання **Розклад: живий перегляд** (`Термінал → Виконати завдання`). Воно запускає отримання актуальної таблиці на **http://127.0.0.1:4173**. Завдання також запитується при відкритті папки: один раз дозвольте автоматичні завдання VS Code, якщо з’явиться відповідний запит.

Звичайний Live Server сам не виконує запити до Google. Тепер, якщо файлів метаданих у ньому немає, сторінка автоматично підключається до завдання на порту 4173. Це зберігає швидкий перегляд змін коду через Live Server і додає живі дані. Сторінка на GitHub Pages ніколи не звертається до localhost відвідувача — вона читає опубліковані workflow файли.

Альтернативно запустіть `node server.cjs` або двічі натисніть **Запустити розклад.cmd**. Для відвідувачів GitHub Pages локальний сервер не потрібен. Якщо живе джерело недоступне або перевірялося понад 20 хвилин тому, позначка збереженої копії залишається з точним часом останньої перевірки. Код не підміняє давність джерела часом відкриття сторінки.

## Оформлення та темна тема

Кругла кнопка **Ір** перемикає світлу й темну теми та зберігає вибір у браузері. До першого ручного вибору використовується системна тема. Перемикання доступне також із клавіатури.

Темна нижня частина використовує чорну й нейтральну сіру палітру, а верхній блок зберігає попереднє оформлення. Смужки всіх типів мають ширину 7 px: лекція — хвиля світла, лабораторна — подвійне сканування, практична — м’яка подвійна пульсація, семінар — зустрічний рух відблисків. У темній темі також збережені анімація градієнта часу та цяточки на картці вільного дня.

Додаткові точки плавно притягуються лише поблизу курсора: при наближенні менш ніж на 145 px вони реагують, а після віддалення понад 210 px повертаються до своїх місць. Різні пороги запобігають різкому перемиканню на межі зони. При системному зменшенні анімацій рух вимикається.

Сайт явно підтримує світлу й темну схеми через `color-scheme` і `prefers-color-scheme`. У темній темі задано окремі контрастні кольори карток, написів, статистики й форм. Перевірено у Chromium з темною схемою та на мобільному розмірі. Примусовий алгоритм перефарбування окремих версій Samsung Internet може відрізнятися від стандартної темної схеми; реальний Samsung Internet у цьому середовищі не запускався.

Верхній фон малює локальний WebGL-ефект світлових площин у сріблясто-графітовій палітрі: повільний рух, змінна інтенсивність, зернистість, плавна реакція світла та паралакс на курсор. Якщо WebGL недоступний, залишається нейтральний CSS-фон. Поза екраном і в прихованій вкладці анімація призупиняється. При зменшенні анімацій показується статичний кадр.

Широку інформаційну смугу прибрано; стан джерела залишається у компактному індикаторі з часом перевірки. Геометрія карток спільна для обох тем: 10/42 px на комп’ютері та 10/24 px на телефоні, з початковим ефектом наведення. Світла картка вільного дня зберігає початковий двошаровий фон без додаткових масок. У темній повторено ті самі шари, кут, прозорість, позиції переходів та розмір точок; змінено лише кольори.

Шапка плавно реагує на гортання вниз і повернення: світло зміщується й розширюється, заголовок злегка піднімається та повертається. Яскравіші частинки розташовані позаду напівпрозорих світлових поверхонь. Промені мають помітніший рух, змінне освітлення й широкий м’який ореол. Градієнт часу рухається без реверсу: повторювана плитка заввишки 384 px проходить рівно 384 px за цикл із тотожними стиками.

Додаткове оформлення: шість світлових шарів зі змінною шириною та вигином; згасання всієї шапки до повного зникнення під час прокручування і плавне повернення. Темні картки приглушені кольорами та тінями без зміни геометрії. Шестерня, плюс додавання, значки приєднання, редагування й мінікартки дня мають короткі анімації взаємодії, які враховують зменшення руху.

Світло шапки розділене на чотири основні площини з чіткою формою та дві окремі передні площини поверх них. У переднього шару масштаб змінюється разом із плавним проявленням і згасанням; базовий шар майже не вигинається.

На екранах до 680 px розклад ущільнено: колонка часу 64 px (58 px на найвужчих екранах), менші відступи, відсутня зайва мінімальна висота, компактні позначки типу й статистика. Перевірено ширини 320 і 390 px в обох темах без горизонтального переповнення. Настільні відступи й форми не змінюються.
