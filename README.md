# Розклад ІР-31

Двічі натисніть **Запустити розклад.cmd**. Він запустить сервер у фоні й відкриє розклад у браузері. Повторний запуск відкриває вже запущений розклад. Потрібен Node.js 20 або новіший.

Альтернативний запуск через термінал:

```powershell
node server.cjs
```

Відкрийте http://127.0.0.1:3000. Потрібен Node.js 20 або новіший.

Сервер читає список аркушів онлайн-книги і сам знаходить поточний аркуш **ВЕБ, ІР, ІРма**, відокремлюючи його від архівних тижнів. Зміна `gid` не потребує ручного редагування: адреса аркуша визначається знову під час кожного оновлення. У налаштування можна вставляти звичайне посилання на онлайн-розклад з `pubhtml#gid=…`; перетворювати його на CSV не потрібно. Старі CSV-посилання також розпізнаються автоматично. Якщо університет створить зовсім іншу книгу з іншим ID, потрібне її нове звичайне посилання.

Розклад оновлюється при відкритті й кожні п’ять хвилин. Запити обходять кеш Google. Форматування червоних дат зберігається. Після успішного завантаження сервер також оновлює офлайн-копію.

Якщо відкрити index.html напряму або розмістити файли на статичному хостингу без /api/schedule, застосунок використовує збережену копію schedule-snapshot.js і показує її точну дату та інструкцію запуску. Для живих оновлень потрібен server.cjs або аналогічний маршрут /api/schedule на хостингу.

Пари без окремих дат повторюються у відповідний день у межах семестру з заголовка таблиці. Дати в квадратних дужках обмежують заняття; червоні дати додають заняття в суботу на час вихідного рядка. Кілька предметів в одному часовому блоці відбираються незалежно за датами.

Парсер також обробляє помилки оформлення з джерела: `(Л )`, `19,10` та зайвий суфікс у діапазоні `28.09.10-26.10`. На 19.10.2026 відображаються чотири заняття: 9:00, 10:30, 12:10 і 13:40.

Перевірки парсера та зміни адреси аркуша: `node --test schedule.test.cjs`.
